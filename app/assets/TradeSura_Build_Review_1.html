TradeSura · Build Review 1

Week-one review & week-two priorities

Review of the TestFlight build (29 screens, 1 Sept 2026) against Build Spec v1. For Oliver, via Rohan.

1. Verdict

Breadth achieved. Core missing. Every screen in the spec exists, navigates, and is built to the design system — on a native iOS build with real SMS verification, a live-looking register check, working phone-contact import, and the reminder and payout screens close to spec. Six days in, that's a real product skeleton and the pace is good.

But the money loop is not reachable: "Set up my plan" errors, Stripe setup errors, and there is no other route to create a plan — so the customer plan page, Direct Debit checkout, Send Offer and Show a Customer can't be tested. The spec's order was money loop first, everything else rough; the build has inverted that. Week two corrects it.

2. Week two — the only goal

By Friday 5 Sept, Matt walks this loop end-to-end on his own phone, in Stripe sandbox:

  1. Plan builder — pick Boiler Care template → price stepper (£8–£25) → earnings preview → toggle inclusions (locked wording) → Make it live
  2. Customer plan page — tradesura.com/p/{engineer} renders his live plan with his name, verified badge, inclusions, "Join" button
  3. Checkout — customer details → Stripe Bacs Direct Debit mandate (sandbox) → confirmation screen → welcome SMS/email
  4. Back on the dashboard — plan count and monthly income update; customer appears as ON PLAN
  5. "My plans" row in More so the builder is always reachable, and the "build your plan" prompts on Offer a Plan / Show a Customer become tappable links

Everything else in this document queues behind these five. If something has to be rough on Friday, let it be UI polish — never the loop.

4. What's right — keep it exactly as it is

  • Design system landed: TS Blue, split wordmark, wash background, one primary action per screen, disabled-until-valid buttons, progress bar, footer trust line with no banned words.
  • Signup step 1: mobile verified by SMS before proceeding, with an honest reason given ("we text your customers' signup links from the app"). Step 3: Partnership type and company number are sensible additions.
  • Trade tiles with SOON + "ticking one registers your interest" — the intent telemetry exactly as intended.
  • Getting Started wizard: four steps, spec copy, right order (rails → plan → book → pack).
  • Phone-contact import works end to end with the imported/updated/skipped summary.
  • Reminders: calendar, 30/14/3-day auto SMS for members, "customer replies to book", one-tap pitch for non-members — this is the spec's intent, landed.
  • Payouts: "This month, transparently" breakdown, Failed collection recovery with Smart Retries, tax-year CSV export.
  • Show a Customer: in-person tagging line means the demo-channel telemetry is wired.
  • Sign-in by email (passwordless) — a better call than the spec's password for this audience.
